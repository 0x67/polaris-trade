# codegen

Wire-schema DSL and generator emitting parse code (borrowed views and match dispatch) for venue feed protocols, plus the record-schema generator behind the `polaris-events` data types. Venue crates are listed under [[venues]].

## Crate layout

One generator crate, `crates/codegen` (package `polaris-codegen`): schema loader and validator [[crates/codegen/src/schema.rs#SchemaFile]], pure emitter [[crates/codegen/src/emit.rs#generate]], IO seam [[crates/codegen/src/cli.rs]], and a thin CLI `main.rs` (write mode, `--check`, `--schema` subset).

A new venue is a new hand-bootstrapped crate shell under `crates/venues/<venue>`; the generator never creates crates. Shared plumbing is [[common]], and the venue crates are [[nasdaq]] and [[sgx]].

## Schema DSL

One YAML per (venue, protocol, major) under `schemas/<venue>/<protocol>/v<major>.yaml`. Frontmatter: `venue`, `protocol`, `doc_version`, `endianness` (required, `be` implemented, `le` rejected).

Per kind: `name` (PascalCase), `byte` (single char, case-sensitive), `byte_len`, ordered `fields` of `{name, width, class}` with classes `u8..i64 | u48 (6-byte BE, accessor zero-extends to u64) | code | alpha`, or `variable: true` (variable-length kinds: raw visitor callback, no generated view, no `BYTE_LEN` entry, no parity). The caller validates a variable message's complete wire slice before dispatch. Optional `since`/`defect` notes are documentation-only. Optional `doc` string on kind and field is emitted as rustdoc at four sites: view struct, field accessor, `MessageType` variant, `HotVisitor` method (docless schemas emit byte-identical output). Validation rejects width-sum mismatches (declared `byte_len` vs 1 + field sum), duplicate bytes/names, bad identifiers, class/width mismatches, banned tokens in `doc` text (spec-process ids, em dash; see [[crates/codegen/src/schema.rs#SchemaFile#validate]]), and identifiers hitting the full strict + reserved Rust keyword list (field names, and kind names whose derived snake_case visitor method collides; either would break generated fn or module names). Optional `major:` integer overrides the doc_version-derived module major when a doc's iteration version differs from the protocol version. Bidirectional order-entry schemas (OUCH) additionally mark every kind `direction: to_exchange | from_exchange` (all-or-none per schema; byte uniqueness is then per direction, so NASDAQ's seven colliding bytes load) and may declare a schema-level `appendage_tags:` TLV registry referenced per kind via `appendage:` name lists plus an `appendage_optional:` dual-form flag; the 2-byte appendage length field is generator-synthesized, never listed in `fields`, and appendage-only kinds with zero fixed rows are legal (NASDAQ AccountQueryRequest is 3 bytes). Model + validation live in [[crates/codegen/src/schema.rs#SchemaFile#validate]]; recv-side emission consuming these keys is live (views/dispatch/BYTE_LEN cover only from_exchange kinds, appendage kinds get fixed/tail split views with min-length parse plus a generated typed tag enum over [[crates/venues/common/src/appendage.rs#AppendageIter]]); builder emission is live (see the generated-boundary section); parity/bench emission is live for directional schemas too (build-then-decode parity for to_exchange kinds, `_empty`/`_full`/`_bare` wire variants for appendage kinds). Committed schemas: `schemas/nasdaq/itch/v5.yaml`, `schemas/nasdaq/ouch/v5.yaml`, and `schemas/sgx/itch/v2.yaml`.

Draft schemas for venues not yet bootstrapped live under `schemas-draft/<venue>/<protocol>/v<major>.yaml`, outside generator discovery (which walks `schemas/` only). A schema moves to `schemas/` only together with its venue crate shell and parity baseline, since write mode refuses schemas without a venue crate and the emitted parity test needs `tests/support/owned_<ns>.rs`. No current drafts: all three promoted schemas are drift-gated, the two feeds (nasdaq itch v5, sgx itch v2) plus the order-entry schema `schemas/nasdaq/ouch/v5.yaml`, whose generated module is assembled into its venue crate. A schema promoted before its module is generated is a legal pre-generation state the drift test tolerates. Onboarding pattern for the next venue: crate shell, doc-only baseline lane, then promote + regenerate via `--schema`.

## Record-schema DSL

Second generator input DSL, separate from the venue-wire `SchemaFile`: it declares the normalized L0-L3 record layout that generates the `polaris-events` data types. Model and the padding walk live in [[crates/codegen/src/record_schema.rs#RecordSchema]]; validation in [[crates/codegen/src/record_schema/validation.rs#RecordSchema#validate]].

The shape is records (a shared header + rtype), plain nestable structs, and an enum registry, expressed directly rather than bolted onto the wire-parser DSL. The committed schema is `schemas/records/l0_l3.yaml` (one file: nine enums, the structs `BidAskPair` and `DefinitionTail`, `RecordHeader`, fourteen records, doc prose carried from the current rustdoc). Wire discovery skips `schemas/records/` ([[crates/codegen/src/cli.rs#discover_schema_paths]]) so the venue-wire pass never tries to load a record schema as a `SchemaFile`.

Field classes ([[crates/codegen/src/record_schema.rs#FieldClass]]): `u8..i64`; `price` (emits `i64`, 1e-9 scale tag, `i64::MAX` null); `flags` (hand-written `RecordFlags`, u16 storage); `bytes` (fixed `[u8; N]`); `enum`/`struct` (a named `EnumDef`/`StructDef` ref); `array` (element class + count). There is no author-facing pad class. A top-level `flags:` registry ([[crates/codegen/src/record_schema.rs#FlagDef]]) declares the `RecordFlags` bit definitions (name + bit); these are the single source for the C header's `MD_FLAG_*` constants and downstream bindings, while the `RecordFlags` type itself stays hand-written logic.

The generator owns padding: [[crates/codegen/src/record_schema.rs#compute_padding]] walks fields in declaration order and inserts `_pad` where `repr(C)` alignment forces it. Interior pad is allowed only before an array or struct (the `Mbp10._pad[5]` before `levels` case, and `Definition._pad[1]` before `tail`); an interior pad before a scalar is rejected as avoidable with a reorder hint; a non-word total (`size` not a multiple of 4) is rejected. Because the author writes no `_pad`, a hand-authored pad cannot be wrong, and the `no_implicit_padding` invariant holds by construction. The walk reproduces every committed `polaris-events` size (`RecordHeader` 56, `Mbo` 96, `Mbp10` 480, `Fill` 96 flush, `Definition` 176 with its nested tail, and the rest), asserted by [[crates/codegen/src/record_schema/validation.rs#RecordSchema#validate]] over the committed file. rtype band placement reuses the same reserved bands as `polaris-events` [[crates/events/src/generated/bands.rs#Category]].

Emission is implemented in [[crates/codegen/src/record_emit.rs#generate_records]] (pure, mirrors the wire `emit::generate`, reuses its provenance header and doc helpers). It writes a Rust tree under `crates/events/src/generated/` (`mod.rs`, `enums.rs`, `header.rs`, `structs.rs`, `records.rs`, `bands.rs` holding the `rtype` inner module + `Category` + `REGISTERED` + `Record` impls) plus a C ABI header at `crates/events/include/md_events.h`. Each record emits `#[repr(C)]` + a `const _: () = assert!(size_of == N)` backstop; the C header ([[crates/codegen/src/record_emit/c_header.rs#emit_c_header]]) emits width-exact enum typedefs, `MD_FLAG_*` bit `#define`s, and an `MD_STATIC_ASSERT(sizeof == N)` per struct (a self-contained `_Static_assert`/`static_assert` shim, no system include), under an `extern "C"` guard so both a C11 and a C++17 front end cross-check every size. Generated records reference `crate::RecordHeader`/`crate::Record` (the `polaris-events` re-exports) so the tree compiles alongside the hand-written types during the transition and again post-swap.

The C header is the ABI pivot for downstream languages: bindings for Python, Go, Node and Java derive from it, and C and C++ consume it directly. The binding pipelines live outside this repository.

The CLI runs a record pass beside the wire pass: [[crates/codegen/src/cli.rs#discover_record_schema_paths]] finds `schemas/records/*.yaml`, `main.rs` generates and write/check/orphan-prunes the tree under `GEN_DIR` (the C header rides the same write/check but is a single fixed path, not orphan-pruned). The committed tree is drift-gated by [[crates/codegen/tests/record_drift.rs#committed_records_are_fresh]] (Rust files and the C header) and rustfmt-ignored (`crates/events/src/generated/`) so nightly fmt never fights the drift gate. `polaris-events` wires it with one `pub mod generated;` line.

A conformance test proved the generated tree size, alignment, and per-field-offset identical to the hand-written types (plus populated-twin byte parity) and gated the swap; the swap is now done. `polaris-events` re-exports the generated types as its record contract ([[crates/events/src/lib.rs]]), and only the logic stays hand-written: the `Record` trait + `decode_prefix`, `Price`, `RecordFlags`, `StatType::band`, `Definition::new`. Going forward the layout is guarded by the retargeted `layout_locked`/`no_implicit_padding`/`fill_layout` tests in `polaris-events` and the codegen drift gate; the transition-only conformance test was removed once both trees no longer coexist. `bands.rs` (not `rtype.rs`) names the file because a file module `rtype` that also contains a `pub mod rtype` self-collides on re-export. Doc-hygiene on schema doc fields reuses the wire DSL's banned-token check.

## Generated-vs-hand-written boundary

A venue crate's generated module tree is machine-written, never hand-edited. 6 + N_fixed files per feed schema: `mod.rs`, `message_type.rs`, `dispatch.rs`, `view/mod.rs`, one `view/<kind>.rs` per fixed kind, parity test, bench (see [[crates/codegen/src/emit.rs#generate]]).

Directional (order-entry) schemas differ: view files cover only from_exchange kinds; a `build/` tree emits one caller-buffer builder per to_exchange kind (full-region init in `new()`, chained `#[inline]` setters, per-registered-tag append methods, `finish() -> usize`); an `appendage.rs` (typed tag enum + iterator) is added when the schema declares a tag registry; the emitted parity test covers both directions (synthetic-bytes view parity for from_exchange kinds, builder build-then-decode parity for to_exchange kinds, `_empty`/`_full`/`_bare` variants for appendage kinds) and the bench adds per-kind builder benches. Builder benches black_box the output buffer, not just `finish()`'s length: the length is a compile-time constant, so observing only it lets the optimizer dead-store-eliminate every setter write and the bench measures loop overhead.

View split: per-kind view files live under a private-mod `view/` directory; `view/mod.rs` re-exports each `<Name>View` so the public path stays `<ns>::view::<Name>View`.

Hand-written and never generated: `crates/common`, venue `lib.rs` (one `pub mod` line per schema), and per-namespace parity baselines under `tests/support/owned_<ns>.rs` (transcribed from venue docs independently of the YAML, so a schema transcription error cannot self-validate; see [[crates/venues/nasdaq/tests/support/owned_itch_v5.rs#decode_owned]]). Builder init space-pads short alpha fields; a venue that null-pads them leaves callers to write full-width bytes via setters, and a per-field pad convention is an open DSL follow-up.

## Drift gate

Generated files carry a provenance header (schema path + sha256, no generator version so release bumps cannot drift the tree); drift tests enforce byte-exact regeneration on every `cargo nextest run`.

[[crates/codegen/src/cli.rs#schema_rel_path]] writes the header's schema path with `/` on every host, so a Windows checkout regenerates the same bytes.

Three layers: the `drift` integration test in `polaris-codegen` fails `cargo nextest run --workspace` on stale or missing output (missing is drift, so a layout mistake cannot pass as "not generated yet"), and lefthook pre-push and CI both run that suite; `cargo run -p polaris-codegen -- --check` repeats that comparison and also reports orphans, which the `drift` test does not check, and no hook or workflow runs it; rustfmt `ignore` entries keep nightly fmt off generated globs so determinism never depends on rustfmt version.

Layout belongs to the caller: [[crates/codegen/src/emit.rs#generate]] and [[crates/codegen/src/emit.rs#owned_module_dir]] take the venue crate directory as an argument, and this repo's binary and drift test pass [[crates/codegen/src/cli.rs#venue_crate_dir]] (`crates/venues/<venue>`). A repo with another layout passes its own directory.

Orphan detection: the generator owns `<crate_dir>/src/<ns>/` recursively ([[crates/codegen/src/emit.rs#owned_module_dir]]). Write mode deletes stray `.rs` files carrying the GENERATED first-line marker and refuses (nothing deleted) on any unmarked file ([[crates/codegen/src/cli.rs#prune_orphans]]); check mode reports every unexpected `.rs` as `orphan:` marker-blind ([[crates/codegen/src/cli.rs#find_orphans]]).

## Inherited emission invariants

Borrowed views and plain `match` dispatch won the decode benchmarks against owned structs and function-pointer tables. Every generated accessor and dispatch path obeys five invariants:

1. **Length pre-validation before view construction.** Two independent checks: dispatcher's caller looks up `message_type::BYTE_LEN[msg_type]` and slices to exact width before calling dispatch thunk; `View::parse` repeats check via `data.try_into()`. Codegen keeps both; thunk `.expect()` only safe because second check exists. `View::parse` (fixed and appendage forms) is emitted `#[inline]` so this check inlines into consumer decode loops across the git-dep boundary; generic dispatch thunks need no attribute (MIR-exported via monomorphization).
2. **No allocation in accessors.** Every accessor is `#[inline]` over `from_be_bytes` read or direct index/sub-slice. No `Vec::new`, `Box::new`, `String::from`, or heap-allocating function calls. The whole parse and accessor path allocates nothing.
3. **Alpha trim behavior.** Alpha accessors return raw, padded, borrowed slice; trimming is separate [[crates/venues/common/src/alpha.rs#trim_alpha]] call, never folded into accessor. Caller pays trim cost only when needed.
4. **Coded single-byte fields stay raw `u8`.** No enum wrapping: `order_verb`, `domicile`, every single-char field returns bare `u8`. Domain enums belong in a layer above this one.
5. **Unknown-kind cold route.** A `msg_type` byte with no dispatch arm/LUT entry routes to `Visitor::cold`, never panics or silently drops. `MessageType::from_byte` returning `None` is dispatcher's same distinction.

## Schema authoring order

Ordering steps for a new schema file transcription (venue doc is read-only primary source):

1. Venue documentation: read the row-field table from venue doc (for example the NASDAQ TotalView-ITCH 5.0 specification).
2. YAML transcription: write kind names (PascalCase), wire type bytes, field names (snake_case), widths, classes to `schemas/<venue>/<protocol>/v<major>.yaml`.
3. Byte-length cross-check: assert `1 + field-widths-sum == byte_len` for every kind against the length table in the venue document.
4. Vendor-header cross-read: verify field offsets and widths against the vendor's C++ struct layouts and the parity baseline. Record discrepancies in `defect:` notes.
5. Parity baseline (separate lanes): hand-transcribe from vendor C++ structs into `crates/venues/<venue>/tests/support/owned_<ns>.rs`, never reading the YAML. Baseline + schema transcribe independently; parity test catches misalignment between them.
